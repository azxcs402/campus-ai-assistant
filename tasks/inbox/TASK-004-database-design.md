## 任务目标

把 [docs/05-database.md](../../docs/05-database.md) 的数据对象草案落成**可执行的数据库设计**：定稿表结构、约束、索引、迁移与种子数据，并解决草案第 4 节列出的决策项。

## 背景和上下文

- 05 文档已定义实体与关系：users、courses、course_members、tasks（父子自关联）、materials、material_chunks、conversations、messages；
- 待决策项（05 文档第 4 节）：选型、迁移/种子、时间口径、删除级联、向量承载方式、最终约束；
- 统计（FR-10/17）为派生数据，不设冗余业务表；
- 提醒（FR-09）基础版以 `tasks.due_at` 查询实现，无独立提醒表。

## 需要修改的文件

- `docs/05-database.md`：状态从草案更新为定稿；回填第 4 节决策项结论；补充建表 SQL/ORM 模型、约束与索引明细、种子数据说明；
- 若字段与 [docs/04-api-spec.md](../../docs/04-api-spec.md) 或需求不一致，同步更新对应文档并在日志记录；
- `docs/vibe-log/`：追加设计落地日志。

## 不允许修改的范围

- 不得修改 `README.md`；
- 不得偏离 05 文档已定义的核心实体关系（新表/大改结构须先更新 05 草案并说明理由）；
- 不得在迁移/种子中引入真实个人信息或任何密钥；
- 本任务产出设计与迁移脚本即可，不实现业务代码（接口层属 TASK-005 及后续实现任务）。

## 完成标准

1. 05 文档定稿：每个实体含字段/类型/约束/索引；实体关系图与建表一致；
2. 决策项 6 条全部有结论并回填；
3. 迁移脚本可执行且可回滚（up/down），在空库上能重建 schema；
4. 种子数据可生成演示环境（含 student/teacher/admin 三类测试账号，密码为测试密码不入库明文，密钥类不出现）；
5. 与 API 字段（04 文档）对齐检查通过：接口用到的每个字段在模型中有定义。

## 测试方法

- 迁移测试：全新环境依次执行迁移 → 校验表/索引存在 → 回滚 → 再执行（幂等）；
- 约束测试：插入违反唯一/外键/枚举的数据应失败并报错清晰；
- 级联测试：删除课程/资料/会话按定稿策略执行且不产生孤儿数据；
- 交叉检查：字段名与 04 API 文档逐一核对。
