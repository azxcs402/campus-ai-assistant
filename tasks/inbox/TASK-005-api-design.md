# TASK-005 · API 设计定稿

- 编号：TASK-005-api-design
- 当前状态：`ready`
- 依赖：TASK-003（技术栈与认证方案）、TASK-004（字段口径）之后执行；为后续前后端实现提供契约

## 任务目标

把 [docs/04-api-spec.md](../../docs/04-api-spec.md) 的草案 v0.1 定稿为**可实现的 API 规格**：完整参数表、枚举、鉴权细节、错误码、限流策略与契约测试，满足标准版"API 文档与测试"要求，并保证基础版「≥ 3 个 HTTP API」门槛被覆盖。

## 背景和上下文

- 04 文档已定义通用约定、6 组接口（认证/课程/任务/资料/对话问答/统计）、错误结构与关键示例；
- RAG 问答（type=rag + citations）、AI 拆解（split → 建议不落库 → batch 确认）等交互已在草案中体现；
- 契约一旦定稿即成为前后端并行开发的依据，变更要走版本化（如向后兼容优先，破坏性变更需在文档记录）。

## 需要修改的文件

- `docs/04-api-spec.md`：更新为定稿（标注基线版本与日期）；补充每个端点的完整请求/响应字段表与示例；
- 定稿 OpenAPI（OpenAPI 3.x）规格文件（位置由 TASK-003 目录结构决定，需在文档中注明）；
- 若定稿过程中发现需求/字段缺口，同步更新 `docs/02-requirements.md` 或 `docs/05-database.md`；
- `docs/vibe-log/`：追加 API 定稿日志。

## 不允许修改的范围

- 不得修改 `README.md`；
- 不得删除基础版必需接口（登录、任务、资料列表、对话、会话记录等，见 02 文档基础版门槛）；
- 不得让任何密钥/供应商配置进入 API 规格或示例；
- 本任务定稿接口契约与契约测试，不实现业务逻辑代码。

## 完成标准

1. OpenAPI 规格覆盖 04 文档全部端点；字段类型/必填/枚举/示例完整；
2. 错误结构全局统一（400/401/403/404/409/429/502/504 语义与 04 第 1 节一致）；
3. 鉴权与权限矩阵明确：每个端点标注角色要求，与 FR-11 AC-11 一致；
4. 契约测试通过：用 mock 网关跑通每端点 200 主分支与至少 400/401/403 分支；
5. 04 文档与 OpenAPI 一致（文档为人类可读入口，OpenAPI 为机器可执行真相，变更同步）。

## 测试方法

- 契约测试（自动化）：请求示例 → 校验响应结构与状态码；
- 边界用例：非法枚举、超长字段、缺参、错误 ID、越权用户（用例可复用 [docs/06-test-plan.md](../../docs/06-test-plan.md) ET 系列）；
- 交叉检查：OpenAPI 与 04/05 文档字段名一致性核对。
