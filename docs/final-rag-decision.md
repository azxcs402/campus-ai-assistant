## 1. 一句话结论（建议）

**不建议在周五前实现"向量 RAG"**；如团队想展示"资料问答"形态，只建议做**零新增依赖、明确命名的"关键词检索 + 资料上下文问答"降级版**，且必须在答辩中如实说明它不是向量 RAG。无论如何，**不得在没有 embedding 与检索实现时声称已实现 RAG**（见第 4 节）。

## 3. 实现"真 RAG"的必要条件（每一项都缺一不可）

1. **文本解析**：至少 TXT/MD 直接可读；PDF/PPTX/DOCX 需额外解析库与时间（`requirements.txt` 现无解析库）——【事实】当前完全缺失。
2. **切分与定位元数据**：文档→chunk，并保留章节/位置用于引用展示（FR-12/AC-12-2）。
3. **Embedding 服务（可用的、经过验证的）**：需要一个 OpenAI 兼容的 `/embeddings` 端点或本地模型。**不能假设 DeepSeek Chat API 自动提供 embedding**——现配置只调用 `/chat/completions`；`api.deepseek.com` 是否有可用的 embedding 端点必须**实测确认**后才能立项（[rag-plan.md](rag-plan.md) 决策项 D-1/D-4）——【事实：无此实测；故 embedding 当前视为不可用】。
4. **向量入库与检索**：存向量、算相似度、取 Top-K（SQLite 存 JSON + 纯 Python 余弦即可，或引入向量库——后者违反"零新增依赖"约束需人工批准）。
5. **课程范围过滤 + 越权防护**：只能检索提问者所属课程的资料（[rag-plan.md](rag-plan.md) §4 有设计）。
6. **生成与引用**：把检索片段注入提示词、要求回答"基于给定资料"，并把来源一并落库返回（FR-14/15）。
7. **诚实拒答规则**：检索无果/置信不足时必须说明"资料中未找到"，不得编造（AC-14-2）。
8. **评估**：≥10~20 条问答评估集，核验"引用真实存在 + 回答来自资料 + 拒答正确"（[06-test-plan.md](06-test-plan.md) §4.1 门槛；5 条样本不足以支撑效果声明）——【建议：至少 10 条】。
9. **演示环境可用性**：演示机网络、Key、供应商端点必须实测，否则现场翻车。

## 4. 当前项目缺少的条件（对照上表）

- 缺 **2、3、4、6** 的代码（解析/切分/embedding/向量/检索/引用，全部为零，事实）；
- 缺 **3 的供应方确认**（embedding 端点未验证、未决策，人工事项）；
- 缺 **8 的评估时间** 与真实课程语料（NFR-04 要求不得用真实个人信息/侵权课件；当前只有合成样例）；
- 缺 **5/7 的落地**（设计已有，未实现）；
- 缺 **回归与演示彩排** 时间（两天内要同时完成代码+评估+文档+彩排，风险高——【推断，按本仓库此前一天完成基础闭环的速度衡量】）。

## 5. 为什么"没有 embedding 却假装已实现 RAG"绝不允许

1. **可核验性**：答辩现场可能要求上传资料现场提问、查看代码、检查数据库/向量。仓库里没有任何 embedding/向量/检索代码（`final-review.md` 2.1~2.3 已列证据），当场即穿帮。
2. **自相矛盾**：前端资料区提示语、Codex 日志、[rag-plan.md](rag-plan.md) 状态都明确写着"未实现/下一阶段"；文档与代码互相矛盾会直接损害可信度。
3. **检索效果无法自证**：没有评估集与引用命中数据，任何"召回率/引用命中/效果良好"的说法都无依据（06 文档要求引用命中率等门槛，未测不能声称达标）。
4. **课程与项目规则**：任务书（七.3"不要虚构已完成功能"）、[AGENTS.md](../AGENTS.md)（5.4 AI 输出必须可溯源、无相关内容如实告知）都禁止虚构实现。
5. **学术诚信**：课程作业评审看重"独立、诚实、可复现"；诚实标注"设计完成、实现待后续"远优于虚假演示。

## 6. 两天内的最低可行方案（若仍要"资料问答"效果）

### 方案 R0（建议优先）——"关键词检索 + 资料上下文问答"降级版（诚实命名，非向量 RAG）

- 范围：仅 TXT/MD（与现有上传白名单一致，无需新解析库）；上传后按段落/标题切分存 `material_chunks`（文本，无向量）；提问时在**当前课程、本人可见**的资料上用关键词/词频匹配取 Top-K 段落；把段落与来源（文件名+章节）注入 chat 提示词；回答下方展示来源；无匹配时明确回复"资料中未找到"。
- 依赖：**零新增**（纯 Python 字符串处理 + SQLite 已有 + 现有 chat 调用）；甚至无网络也能跑通演示模式路径的说明。
- 工作量估计：1~1.5 天主体 + 0.5 天评估/彩排（【推断】；对比基础闭环此前约 1 天完成的速度）。
- 命名口径：**这是"基于资料的检索问答（RAG 的轻量降级，无向量）"，不是向量 RAG**。若团队只追求演示效果可接受，则采用。
- 风险：关键词检索对"同义/概念级"问题召回弱——演示问题必须选语料中字面相关的（见 [rag-demo-dataset.md](rag-demo-dataset.md) 语料，如"时间片轮转"类），并如实说明局限。

### 方案 R1——真向量 RAG 最小版（仅当 embedding 已确认可用）

- 前置（不可省略，且需人工决策）：embedding 端点实测可用并有 Key（决策项 D-1/D-4）；允许按需引入解析库/向量库的决策（D-2/D-3）。
- 两天排期参考 [rag-plan.md](rag-plan.md) §8（Day1 解析+入库；Day2 向量+问答+引用+前端+评估），并按第 3 节 1~9 全项验收。
- 判断标准：Day 1 结束前若 embedding 端点仍不可用/未批准，**立即切换 R0 或放弃实现**，把剩余时间用于彩排与口径。

## 7. 不实现 RAG 时，答辩中如何解释（话术模板，可逐句使用）

1. **先讲已实现的事实**："系统已完成任务管理、统计、资料上传与存储、AI 对话与记录保存的完整闭环，全部为可运行代码与接口测试覆盖。"
2. **主动交代资料能力的边界**："课程资料目前支持上传、列表与本地持久化；我们**没有**把'上传'讲成'能被 AI 检索'——文本解析与基于资料的问答是设计好的下一步。"
3. **说明为什么没在本周五前做向量 RAG（给理由，不找借口）**："RAG 的必要条件是 embedding 服务。我们的模型接入点是 OpenAI 兼容的 chat 接口，`/embeddings` 端点未配置也未实测；在缺少 embedding 的情况下强行拼一个'假 RAG'（没有向量、没有检索、没有来源校验）无法通过'引用真实性'的核验，反而违背课程对独立、诚实实现的要求。"
4. **展示设计与规划（把"没实现"讲成"有计划"）**："我们已产出两天实现方案（[rag-plan.md](rag-plan.md)：切分→向量→Top-K 检索→带引用回答→拒答规则）和演示语料与 5 个验收问题（[rag-demo-dataset.md](rag-demo-dataset.md)），包括一道'资料里没有答案'的问题来验证系统不会编造。这体现我们理解 RAG 的完整链路与风险。"
5. **给出路线与可验证的下一步**："下一步在 embedding 服务可用后，按方案落地并配套 ≥10 条评估问题验证'引用真实、回答来自资料、无据拒答'三条标准。"
6. **被追问"能现场演示资料问答吗"**："可以演示资料**管理**闭环；基于资料的智能问答是计划功能，为避免误导，我不会把它演示成已实现。如果您想看，我可以展示设计方案与预期交互。"（配合 [final-demo-checklist.md](final-demo-checklist.md) §3 话术）

## 8. 结论落点

- 周五前**建议不做真 RAG**；可选做 R0 降级检索（需先在 Day1 上午验证：TXT/MD 解析+关键词检索能否在半天内跑通——跑不通立即放弃）。
- 无论如何：**资料状态文案先修正**（P0-1，见 [final-review.md](final-review.md)），避免"待解析"造成已实现解析的误读。
- 答辩以 [final-demo-checklist.md](final-demo-checklist.md) 的主线为准，RAG 一律按本文件第 7 节口径表述。
