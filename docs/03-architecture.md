# 03 · 系统架构（Architecture）

> 文档编号：03 ｜ 状态：概念架构（草稿）｜ 技术选型待 `tasks/inbox/TASK-003-system-architecture.md` 决策后在本文件固化
> 关联：[02-requirements.md](02-requirements.md)（能力与边界）、[04-api-spec.md](04-api-spec.md)（接口）、[05-database.md](05-database.md)（数据）。

## 1. 架构目标与原则

1. **可演示、可演进**：基础版先跑通闭环，RAG 等能力以后端服务形式增量叠加，不推翻已有结构。
2. **分层清晰**：前端只通过 HTTP API 访问后端；AI/RAG 密钥只存在于后端。
3. **AI 组件可替换**：LLM / Embedding / 向量库都抽象为接口，便于课程演示环境切换供应商或本地模型。
4. **范围克制**：单机/课程演示级部署，不引入微服务、消息队列等重设施；可选功能（外部渠道、语音等）不得影响主链路。
5. **不预设技术栈**：本文件描述组件职责与关系；具体框架/库由 TASK-003 决策，决策结果回写本文档「附录 A 技术选型」。

## 3. 组件职责

### 3.1 Web 前端

- 页面与交互（见 [01-design-thinking.md](01-design-thinking.md) 第 4 节六个流程）；
- 状态管理：登录态、当前课程/任务列表、消息流；
- **不存储也不接触任何 LLM/DB 密钥**；AI 能力一律经后端 API 使用；
- 响应式，保证手机浏览器可用（NFR-06）。

### 3.2 后端应用服务

| 模块 | 职责 | 对应需求 |
| --- | --- | --- |
| 认证/用户 | 注册、登录、会话（token）、角色 | FR-01、FR-11 |
| 任务/课程 | 任务与课程的 CRUD、筛选、完成状态 | FR-02、FR-03、FR-09 |
| 资料管理 | 资料元数据、上传、解析状态机（排队/处理/可问答/失败） | FR-04、FR-05 |
| 对话会话 | 会话与消息持久化、多轮上下文 | FR-06、FR-07 |
| AI 编排 | 调用 AI 网关：普通对话、任务拆解、RAG 问答组装 | FR-06/16/14 |
| 统计聚合 | 完成率与趋势数据计算（读模型，不写业务源） | FR-10、FR-17 |
| 统一中间件 | 鉴权、参数校验、统一错误结构（FR-08）、日志 | FR-08 |

### 3.3 AI 网关（接口抽象层）

- 统一封装 **LLM 对话/生成** 与 **Embedding 向量化** 两类能力，屏蔽具体供应商；
- 提供统一超时、重试、错误码与**降级策略**：AI 不可用时，任务/资料等非 AI 功能不受影响（NFR-05）；
- 所有调用密钥仅存在于后端配置/环境变量，遵守 [AGENTS.md](../AGENTS.md) 提交禁令。

### 3.4 RAG 管线（特色版）

1. **解析与切分（FR-12）**：抽取文本，按标题/段落/页面切分为 chunk，chunk 携带定位元数据；
2. **向量索引（FR-13）**：chunk → embedding → 写入向量库；资料变更（增/删/覆盖）时索引同步；
3. **检索（FR-14）**：问题向量化后检索 Top-K 相关 chunk，默认限定当前课程范围；
4. **生成与溯源（FR-14/15）**：把检索结果作为上下文交给 LLM 回答，回答与来源一并返回前端。

### 3.5 数据与存储

| 存储 | 内容 | 关系 |
| --- | --- | --- |
| 业务数据库 | users、courses、course_members、tasks、materials、conversations、messages、material_chunks（元数据）等 | 见 [05-database.md](05-database.md)；所有业务事实的唯一来源 |
| 原始文件存储 | 上传的课程资料文件（按课程/用户组织） | materials 表记录路径与元数据 |
| 向量索引库 | chunk 的向量与文本 | 可由业务 DB 的衍生表或专用向量库承载（TASK-003 决策） |

## 4. 关键数据流

### 4.1 登录（FR-01）
前端 → `POST /auth/login` → 认证模块校验 → 签发会话 token → 前端保存并在后续请求携带 → 鉴权中间件校验（未登录 401、越权 403）。

### 4.2 创建任务并触发"即将截止"（FR-02/09）
前端 → `POST /tasks` → 任务模块校验字段并落库 → 查询侧按服务器时间计算即将截止集合 → 返回更新后的列表/视图数据。

### 4.3 资料上传 → 可问答（FR-05/12/13）
前端 → `POST /materials`（multipart）→ 资料模块保存文件+元数据 → **异步任务**：解析 → 切分 → embedding → 写向量库 → 更新解析状态 → 前端轮询/查询状态直至"可问答"或"失败"。

### 4.4 RAG 问答（FR-14/15）
前端 → `POST /conversations/{id}/messages`（带课程范围）→ AI 编排：向量检索 → 组装上下文 → LLM 回答 → 会话模块落库（问题+回答+来源引用）→ 返回回答与来源。

### 4.5 AI 任务拆解（FR-16）
前端 → `POST /tasks/{id}/split` → AI 编排调用 LLM 生成子任务建议（结果**不自动落库**）→ 前端逐条编辑确认 → `POST /tasks`（批量）落库关联父任务。

## 5. 错误处理与一致性约定

- 统一错误结构 `{ "code": ..., "message": ..., "details": [...] }`（见 [04-api-spec.md](04-api-spec.md)）；
- 状态码语义：400 参数错误 / 401 未认证 / 403 越权 / 404 不存在 / 409 冲突（如重复提交）/ 429 限流 / 500 与 502/504（AI 网关）区分；
- 上传解析状态机必须幂等：同一资料重复触发解析不产生重复 chunk（FR-13 覆盖）；
- 前端显示与后端状态以接口返回为准，避免本地时间/状态漂移（AC-09-2）。

## 6. 安全边界

1. 密钥仅存后端，`.env` 不入库（[AGENTS.md](../AGENTS.md) 强制）；
2. 密码哈希存储；token 有有效期；
3. 越权访问后端拦截（FR-11 AC-11-4）；
4. 上传内容类型与大小白名单（FR-05），防止任意文件与超大文件；
5. AI 输入输出做长度/内容基本约束，防止注入与滥用（FR-08）。

## 7. 部署与运行形态（演示级）

- 单机即可部署：后端进程 + 数据库 +（特色版）向量库 + 静态前端（或由后端托管构建产物）；
- 环境变量注入 AI 供应商配置；无外网 AI 时系统仍可演示全部非 AI 功能；
- 提供一键启动/演示脚本属于实现任务范畴，由 TASK-003 后的实现任务落地。

## 附录 A · 技术选型

本期 MVP 采用轻量单机方案，优先保证两天内可运行和可演示：

| 层次 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | Python + FastAPI | 快速提供类型校验、OpenAPI 和 REST API |
| 数据库 | SQLite + 原生 SQL | 无额外服务，适合课程演示和本地持久化 |
| 前端 | HTML + CSS + 原生 JavaScript | 不依赖前端构建工具，降低启动和部署风险 |
| AI | OpenAI 兼容 HTTP 接口 | 可接入 DeepSeek 等供应商，未配置时使用演示降级 |
| RAG | 后续阶段再接入 | 先保证基础业务闭环，再验证特色技术 |

该选型保留了后续替换前端框架、数据库和 AI 供应商的空间，符合 NFR-09。
