# 02 · 需求文档（Requirements）

## 1. 版本分层与交付范围

| 版本 | 定位 | 内容 | 状态 |
| --- | --- | --- | --- |
| 基础版（MVP） | 可运行、可演示的闭环 | FR-01/02/03/04/06/07/09 + ≥3 个 HTTP API + 数据库持久化 + 前端展示后端数据 | 规划中 |
| 标准版 | 角色、健壮性与数据价值 | FR-05/08/10/11/17 + API 文档与测试 | 规划中 |

版本推进顺序：基础版 → 标准版 → 特色版；标准版在基础版上叠加，特色版依赖标准版的资料上传能力（FR-05）。

## 2. 功能需求（FR）

> 验收标准缩写：AC（Acceptance Criteria）。详细测试设计见 [06-test-plan.md](06-test-plan.md)。

### 基础版（MVP）

| 编号 | 名称 | 需求描述 | 验收标准（AC） |
| --- | --- | --- | --- |
| FR-01 | 用户注册与登录 | 学生用学号/账号 + 密码注册并登录；登录态会话保持；可退出登录 | AC-01-1 注册成功后可立即登录；AC-01-2 错误密码给出明确提示且不泄露账号是否存在（统一提示）；AC-01-3 未登录访问受保护页面跳转登录页；AC-01-4 刷新/重开页面会话不丢失（会话有效期 ≥ 演示时长） |
| FR-02 | 学习任务管理 | 任务增删改查；字段含任务名、所属课程、截止时间、优先级、备注、完成状态；支持按课程/状态筛选与"即将截止"排序 | AC-02-1 新建任务后列表可见且字段完整；AC-02-2 可编辑除 ID 外的全部字段；AC-02-3 删除需二次确认；AC-02-4 任务可标记完成/未完成；AC-02-5 筛选与排序在刷新后仍生效（由前端状态或查询参数承载） |
| FR-03 | 课程管理 | 学生创建/加入课程，维护课程名与学期等基本信息；任务与资料均挂靠课程 | AC-03-1 学生可创建课程并自动成为成员；AC-03-2 课程列表可见且可进入详情；AC-03-3 删除课程需处理其下任务与资料（阻止删除或级联确认，二者择一并写明） |
| FR-04 | 课程资料列表 | 按课程查看资料列表（文件名、类型、大小、上传时间、解析状态），资料由后端数据渲染 | AC-04-1 资料列表与数据库内容一致；AC-04-2 空课程给出空状态引导；AC-04-3 基础版资料以"课程-文件名"为最小组织单位 |
| FR-06 | AI 文本对话 | 提供普通文本对话（不依赖课程资料上下文）；支持连续多轮 | AC-06-1 发送消息后返回 AI 回复；AC-06-2 多轮上下文连续（同一会话内 AI 能引用前文）；AC-06-3 AI 服务不可用时返回可读错误并支持重试 |
| FR-07 | 对话记录保存 | 会话（对话列表）与消息持久化到数据库；历史会话可回看与继续 | AC-07-1 每次消息（用户与 AI）落库；AC-07-2 会话列表按时间倒序；AC-07-3 打开历史会话能加载完整消息序列并继续对话 |
| FR-09 | 截止提醒与即将截止视图 | 首页展示"即将截止"任务；按配置提前 N 天/小时在系统内提醒（基础版以内置视图+站内提示为主，外部推送为可选） | AC-09-1 即将截止区按截止时间升序且高亮 24 小时内任务；AC-09-2 数据按服务器时间计算，不依赖用户设备时钟；AC-09-3 提醒文案包含任务名与剩余时间 |

> 基础版工程门槛（来自任务书，全部必须满足）：① 用户登录；② 学习任务增删改查；③ 课程资料列表；④ AI 文本对话；⑤ 对话记录保存；⑥ 至少 3 个 HTTP API；⑦ 数据库持久化；⑧ 前端展示后端返回的数据。

### 标准版

| 编号 | 名称 | 需求描述 | 验收标准（AC） |
| --- | --- | --- | --- |
| FR-05 | 课程资料上传 | 上传文件到指定课程；校验格式与大小；同名文件策略明确；展示解析状态（排队/处理中/可问答/失败）；失败可删除重传 | AC-05-1 支持 PDF/PPT/Word/TXT 等常见文本类格式，不支持格式给出明确提示；AC-05-2 超限文件被拒绝并提示上限；AC-05-3 上传进度可感知；AC-05-4 失败状态可识别原因并允许重传 |
| FR-08 | 异常输入与边界处理 | 全局处理：必填校验、格式校验、非法 ID、越权访问、超长输入、重复提交；错误信息统一格式且不泄露内部细节 | AC-08-1 非法请求返回统一错误结构（见 [04-api-spec.md](04-api-spec.md)）；AC-08-2 必填缺失/格式错误的字段逐项提示；AC-08-3 访问他人资源返回 403/404（不暴露资源存在性）；AC-08-4 超长文本截断或拒绝并有说明；AC-08-5 前端按钮防重复提交 |
| FR-10 | 任务完成率统计 | 按课程/时间段统计任务总数、已完成、逾期数与完成率 | AC-10-1 完成率 = 已完成 / 总数（口径写明是否含逾期）；AC-10-2 无任务课程显示 0% 或"—"；AC-10-3 时间范围过滤正确 |
| FR-11 | 角色与权限控制 | 学生 / 教师 / 管理员三角色；资源访问按角色与归属校验 | AC-11-1 学生只能读写自己的任务、资料与对话；AC-11-2 教师可管理自己名下课程（发布任务/资料为后续项，本期至少可查看所授课程概况）；AC-11-3 管理员可管理用户与全局数据；AC-11-4 后端强制鉴权，前端隐藏不等于安全 |
| FR-17 | 学习数据可视化 | 对统计结果做图表展示（课程完成率对比、完成趋势等） | AC-17-1 图表数据与 FR-10 统计接口一致；AC-17-2 数据为空/全零时有占位说明；AC-17-3 图表适配常见浏览器与手机屏幕 |

> 标准版额外工程要求：API 文档（含参数与示例）与 API 测试（见 [04-api-spec.md](04-api-spec.md)、[06-test-plan.md](06-test-plan.md)）。

### 特色版（RAG）

| 编号 | 名称 | 需求描述 | 验收标准（AC） |
| --- | --- | --- | --- |
| FR-12 | 资料解析与切分 | 对上传的文本类资料解析文本并切分为检索单元（按标题/段落/页等），记录切分来源定位信息 | AC-12-1 主流 PDF/PPT/TXT 可解析出文本；AC-12-2 切分单元携带可定位元数据（文件名+章节/页码）；AC-12-3 解析失败有明确原因记录 |
| FR-13 | 向量索引建立 | 对切分单元生成向量并写入向量索引；资料删除/重新上传时索引同步更新 | AC-13-1 每个切分单元可检索；AC-13-2 删除资料后其索引条目被清除；AC-13-3 重新上传同名文件后问答使用新内容 |
| FR-14 | 检索增强回答 | 用户提问时，仅从所选课程（或全局）资料检索相关内容，交给 AI 生成带上下文的回答 | AC-14-1 回答基于检索到的片段而非仅靠模型记忆；AC-14-2 无相关内容时回答明确说明"资料中未找到"，不得编造；AC-14-3 检索范围默认限定当前课程 |
| FR-15 | 答案来源展示 | 回答同时展示引用来源（文件名/章节/页码/片段预览），可点击跳转定位 | AC-15-1 每条关键回答至少展示一个可点击来源；AC-15-2 来源与检索片段一致，不虚构引用；AC-15-3 无来源时的说明性回答不展示来源 |
| FR-16 | AI 学习任务智能拆解 | 对一个大任务调用 AI 生成子任务建议（名称、建议日期、预估时长）；用户可编辑、删除、增补、重新生成；确认后写入任务表 | AC-16-1 生成 3–8 条子任务且每条可单独编辑；AC-16-2 支持重新生成（消耗可控）；AC-16-3 确认后子任务出现在任务列表并关联父任务；AC-16-4 AI 不可用时允许手动添加，不阻断 |

## 3. 非功能需求（NFR）

| 编号 | 类别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 常规页面接口 P95 响应 < 500ms（AI/RAG 类接口除外） | 演示数据量下满足 |
| NFR-02 | 性能 | AI 文本对话首字延迟可接受（< 10s），RAG 检索+回答 < 30s | 超时给出明确提示 |
| NFR-03 | 安全 | 密码不明文存储（哈希）；密钥只存后端；接口校验身份与权限 | 代码评审 + 渗透自测基本项（越权、注入） |
| NFR-04 | 安全与合规 | 不收集非必要个人信息；上传资料仅用于本人问答 | 隐私声明写入演示说明 |
| NFR-05 | 可靠性 | 数据库持久化，重启不丢业务数据；AI 服务故障不影响非 AI 功能 | 重启冒烟测试通过 |
| NFR-06 | 可用性 | 关键流程 3 步内可达；移动端浏览器可用（响应式） | 原型/界面走查 + TASK-006 结果 |
| NFR-07 | 可维护性 | 前后端分层清晰；文档与代码同步；模块单一职责 | 架构评审（TASK-003）通过 |
| NFR-08 | 可测试性 | 核心接口可自动化测试；AI 输出有离线评估集 | 见 [06-test-plan.md](06-test-plan.md) |
| NFR-09 | 依赖约束 | 不引入无必要依赖；RAG/LLM 组件可替换（接口化） | 依赖清单评审 |

## 4. 待验证假设 → 需求影响清单

| 假设（出处见 01 文档） | 若成立 | 若不成立 |
| --- | --- | --- |
| H1 录入成本可接受 | 保持任务手动创建为唯一入口 | 增加批量导入/从课程平台同步（需人工决策） |
| H2 提醒能减少漏任务 | FR-09 强化为主动提醒 | FR-09 降级为纯视图 |
| H4 用户信任带来源的资料问答 | FR-12~15 保持为特色主线 | 弱化 RAG，保留普通对话（FR-06/07） |
| H5 用户愿意采纳 AI 拆解结果 | FR-16 保持"建议+编辑"形态 | 降为纯手动子任务模板 |
| H6 学生侧即可形成价值闭环 | 教师功能延后（现状） | 需提前教师侧（I7），范围扩大 |

## 5. 范围红线（Out of Scope）

- 不做教师发布任务/学生共享资料的完整功能（I6/I7，见 [01-design-thinking.md](01-design-thinking.md) 3.4）；
- 不做 Live2D、语音、QQ/Telegram 渠道、复杂本地文件操作；
- 不做多租户/高并发/生产级运维能力；
- 不引入与上述需求无关的技术与依赖。
