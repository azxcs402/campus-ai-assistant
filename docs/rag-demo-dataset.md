## 2. 合成样例语料（内嵌，上传时使用本段内容生成 `os-process-scheduling-demo.md`）

```markdown
# 操作系统 · 进程调度讲义（演示节选）

## 1 什么是进程调度

### 1.1 为什么需要调度
一台计算机上往往同时运行多个进程，而 CPU 数量有限（本讲义假设单核），
同一时刻只能有一个进程占用 CPU。操作系统必须决定“下一个轮到谁运行”，
这就是进程调度要解决的问题。

### 1.2 调度的定义
进程调度（Process Scheduling）指操作系统按照某种策略，从就绪队列中选择
一个进程，并把 CPU 分配给它运行的过程。负责做这个选择的程序叫调度程序
（Scheduler）。

### 1.3 调度的触发时机
进程调度通常在以下时刻发生：(1) 新进程进入就绪队列；(2) 正在运行的进程
因等待输入输出或某个事件而阻塞、或运行结束；(3) 时间片用完；(4) 抢占式
调度下，更高优先级的进程到达。

## 2 调度的目标

### 2.1 公平性
每个进程都应获得合理的 CPU 份额，避免某些进程长期得不到运行，这种现象
称为饥饿（starvation）。

### 2.2 高效
尽量提高 CPU 利用率和吞吐量。吞吐量指单位时间内完成的进程数量。

### 2.3 及时
减少进程的等待时间与周转时间。周转时间指进程从进入系统到运行完成的总
时间；交互式系统还要关心响应时间。

### 2.4 目标之间的权衡
公平、高效、及时三类目标常常互相冲突。例如一味追求吞吐量可能让交互任务
等待过久；一味追求公平则可能牺牲系统效率。实际系统要按自身类型取舍。

## 3 常见调度算法

### 3.1 先来先服务（FCFS）
按进程到达就绪队列的先后顺序调度。实现简单、比较公平；但如果一个长进程
先到，后来的短进程都要排队等它，形成“护航效应”，平均等待时间可能变长。

### 3.2 短作业优先（SJF）
每次选择预计运行时间最短的进程。理论上它使平均等待时间最短，但需要预先
知道每个进程的运行时间；而且长作业可能长期得不到运行，同样会出现饥饿。

### 3.3 时间片轮转（Round Robin，RR）
就绪队列按到达顺序排队，每个进程最多连续运行一个时间片 q；时间片用完就
把它移到队尾重新排队。RR 响应快、基本不会饿死进程；但 q 太小会使进程切
换开销显著上升，q 太大则退化成先来先服务。

### 3.4 优先级调度
每次选择优先级最高的进程运行，可分抢占式与非抢占式。低优先级进程可能
一直等不到 CPU（饥饿），常见对策是“老化（aging）”：进程等待越久，系统
越提高它的优先级。

## 4 综合示例：时间片轮转的计算

就绪队列中依次有 P1（还需 8ms）、P2（还需 4ms）、P3（还需 2ms），三个进程
同时到达，时间片 q = 4ms：

- 0–4ms：P1 运行一个时间片，剩余 4ms，排到队尾；
- 4–8ms：P2 运行完毕（用满 4ms）；
- 8–10ms：P3 运行完毕（只用 2ms）；
- 10–14ms：P1 运行完毕（补足剩余 4ms）。

完成顺序为 P2 → P3 → P1。平均等待时间 = (6 + 4 + 8) ÷ 3 = 6ms；
平均周转时间 = (14 + 8 + 10) ÷ 3 ≈ 10.7ms。

## 5 小结与易错点

### 5.1 按场景选算法
批处理系统重吞吐，常用 FCFS、SJF；交互式系统重响应，常用 RR 类算法；
实时系统则要优先保证截止时间。

### 5.2 两个易错点
第一，SJF 的“最优”建立在进程同时到达、且能预知运行时间两个前提上；
第二，RR 的时间片不是越小越好，频繁切换带来的开销也必须计入总开销。
```

### 问 1（定义型）｜什么是进程调度？什么情况下操作系统会触发一次调度？

- **期望回答要点**：① 从就绪队列中按策略选一个进程并把 CPU 分配给它运行；② 负责选择的是调度程序；③ 触发时机至少覆盖：新进程进入就绪、当前进程阻塞/结束、时间片用完、更高优先级进程到达（抢占式）。
- **期望引用来源**：`os-process-scheduling-demo.md` → 1.2 调度的定义、1.3 调度的触发时机。
- **人工核验引用真实性**：把回答中的每个论断对照 chunk 原文逐句比对（可在前端点开 snippet）；两小节标题须出现在 citations 的 `location` 中。

### 问 2（目标型）｜进程调度要追求哪些目标？为什么说这些目标需要权衡？

- **期望引用来源**：`os-process-scheduling-demo.md` → 2.1 公平性、2.2 高效、2.3 及时、2.4 目标之间的权衡。

### 问 3（计算型）｜就绪队列依次有 P1（还需 8ms）、P2（4ms）、P3（2ms），时间片 4ms，用时间片轮转，完成顺序和平均等待时间是多少？

### 问 4（辨析型）｜短作业优先是不是总是最好的？它有什么缺点，怎么处理进程饿死的问题？

- **期望回答要点**：① 理论上平均等待时间最短，但不是无条件最优；② 缺点：需要预先知道运行时间、长作业可能饥饿；③ 对策：老化（aging）——随等待时间提高进程优先级（注意语料中 aging 出现在优先级调度的语境，回答应说明这是针对优先级调度饥饿的常用对策，不夸大）。
