## 1. 项目名称与代号

- 项目名称：**基于 AI 与 RAG 的校园智能学习助手系统**
- 代码代号：`campus-ai-assistant`（仓库名沿用）
- 公开项目链接：https://github.com/azxcs402/campus-ai-assistant
- 课程背景：《系统设计与实践》。课程要求项目从真实用户需求出发，依次经过用户调研、问题定义、方案构思、原型验证，再进入系统设计与工程实现。
- 技术参考：[EchoBot](https://github.com/KdaiP/EchoBot)（AI 对话、意图识别、Agent 工具调用、会话记录、定时任务、资料检索）。EchoBot 仅作为技术思路参考，**不得复制其代码**；本项目必须拥有独立的校园学习场景、独立的需求分析与系统设计。

## 2. 项目目标

面向**大学生**，解决四类真实困扰：

1. 学习任务分散在多个渠道，容易漏看、漏交；
2. 课程资料散落难查找，复习时找不到出处；
3. 大作业/论文缺少拆解方法，计划难以执行；
4. 容易错过截止时间，缺乏提醒与进度感知。

系统最终交付形态：**一个可以运行和演示的前后端系统**（含数据库、HTTP API、前端界面与 AI/RAG 能力），而不是只有聊天页面的普通聊天机器人。

## 3. 项目范围

### 3.1 初步功能方向（来自任务书，需经设计思维筛选）

| 方向 | 说明 |
| --- | --- |
| 学习任务管理 | 集中登记课程任务与截止时间，增删改查 |
| 课程资料管理 | 按课程组织上传的资料文件 |
| 基于课程资料的 AI 问答 | 对资料做 RAG，回答并显示来源 |
| 学习任务智能拆解 | AI 把大任务拆成可执行子任务 |
| 学习提醒 | 临近截止时间进行提醒 |
| 学习数据统计 | 完成率、进度统计与可视化 |

### 3.2 版本分层（与工程交付节奏对应，见 [02-requirements.md](02-requirements.md)）

- **基础版（MVP）**：可运行闭环 —— 登录、任务 CRUD、资料列表、AI 文本对话、对话记录保存、≥3 个 HTTP API、数据库持久化、前端展示后端数据。
- **标准版**：角色与权限（学生/教师/管理员）、资料上传、完成率统计、数据可视化、异常输入处理、API 文档与测试。
- **特色版**：以 **RAG** 为主要特色技术 —— 文档解析切分、向量索引、检索增强回答、答案来源展示。
- **可选功能（不影响基础交付）**：Live2D、语音、QQ/Telegram 渠道、复杂本地文件操作。

### 3.3 角色

| 角色 | 代号 | 主要职责（初步，待需求细化） |
| --- | --- | --- |
| 学生 | `student` | 管理个人任务、上传/查看课程资料、基于资料提问、查看统计 |
| 教师 | `teacher` | 管理自己课程与资料、查看所授课程任务情况（标准版起） |
| 管理员 | `admin` | 系统与用户管理、数据维护（标准版起） |

### 3.4 明确不做（当前范围之外）

- 不做与校园学习场景无关的通用聊天机器人；
- 不做 Live2D、语音、QQ/Telegram 等渠道集成（可选，优先级最低）；
- 不做复杂的本地文件系统操作；
- 不追求大规模并发与生产级运维，目标环境为课程演示/单机部署。

## 4. 核心价值主张

> 学生需要一个**单一入口**来掌握「我的课程 → 我的任务与截止时间 → 我的资料 → 针对资料的提问」，并在 AI 的帮助下把大任务拆成今天就能开始的下一步。

## 5. 关键约束

- 有真实用户需求依据，但当前访谈数据**尚未收集**，凡涉及用户行为与动机的结论均为「待验证假设」（见 [01-design-thinking.md](01-design-thinking.md)）。
- 不引入无必要的技术与依赖；技术选型由 TASK-003 决策后在 [03-architecture.md](03-architecture.md) 固化。
- 不提交任何 API Key / `.env` / 真实个人信息。
