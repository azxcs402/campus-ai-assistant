## 1. 项目概述

校园智能学习助手面向大学生的课程学习场景，将课程、学习任务、截止时间、课程资料和 AI 学习助手集中到同一个 Web 系统中。

项目当前版本定位为可运行、可演示的课程项目，重点验证以下工程闭环：

1. 用户注册并登录系统。
2. 用户创建课程并维护学习任务。
3. 任务数据通过前端、后端 API 和 SQLite 持久化。
4. 页面根据后端返回的数据更新任务、统计和资料列表。
5. 用户可以使用普通 AI 文本对话，并保存会话与消息记录。
6. 系统对权限、非法输入、文件格式和 AI 服务故障进行基本处理。

当前版本不把资料解析、向量检索、RAG 问答或 AI 任务拆解写成已实现功能。这些能力保留在特色版规划中。

## 2. 背景与需求

### 2.1 使用场景

项目针对大学生在多门课程并行学习时可能遇到的任务记录和资料整理问题。当前用户画像、痛点频率和需求优先级属于待验证假设，尚未用真实访谈或原型测试形成用户事实。

项目将以下场景作为设计输入：

- 课程任务分散在课程群、教务通知和个人记录中。
- 不同任务的截止时间、优先级和完成状态不易统一查看。
- 课程资料和任务缺少按课程组织的入口。
- AI 的回答如果不能回到具体任务，难以形成可执行行动。

### 2.2 需求分层

| --- | --- | --- |

| 标准版 | 资料上传校验、异常处理、统计、最小角色权限和数据图表 | 已实现最小版本 |
| 特色版 | 资料解析、向量检索、RAG 引用回答和 AI 任务拆解 | 计划中 |

## 3. 系统总体架构

### 3.1 架构分层

系统采用前后端分离结构：

```text
浏览器前端
HTML / CSS / JavaScript
        │
        │ HTTP JSON / multipart API
        ▼
FastAPI 后端
认证、权限、课程、任务、资料、会话、统计、AI 网关
        │
        ├── SQLite 数据库
        ├── 本地资料文件目录
        └── OpenAI 兼容 AI 服务（可选）
```

前端不直接连接数据库，也不在源码中保存 AI 密钥。所有业务数据通过后端接口读写，后端负责身份认证、参数校验和资源归属检查。

### 3.2 技术选型

| 层次 | 技术 | 选择原因 |
| --- | --- | --- |
| 前端 | 原生 HTML、CSS、JavaScript | 无构建步骤，适合课程演示和快速验证 |
| 后端 | Python + FastAPI | 提供类型校验、REST API 和 Swagger 文档 |
| 数据库 | SQLite | 无需额外数据库服务，适合本地单机项目 |
| 文件存储 | `data/uploads/<course_id>/` | 按课程隔离上传资料，结构简单可检查 |
| AI 接入 | OpenAI 兼容 HTTP API | 可切换 DeepSeek 等供应商，保留接口替换空间 |
| 测试 | pytest、FastAPI TestClient、mock provider | 支持离线验证，不依赖真实 API Key |

### 3.3 运行形态

- 后端监听 `127.0.0.1:8000`。
- 前端由 Python 静态服务器监听 `127.0.0.1:5500`。
- Swagger 地址为 `http://127.0.0.1:8000/docs`。
- 上述地址是本机运行地址；对外提交与代码访问使用公开 GitHub 仓库：https://github.com/azxcs402/campus-ai-assistant。
- 数据库默认位于 `data/app.db`。
- 上传文件默认位于 `data/uploads/`。

## 4. 核心业务流程

### 4.1 登录流程

1. 用户提交账号、密码和昵称。
2. 后端校验字段并生成密码哈希。
3. 注册成功后返回用户信息和访问令牌。
4. 登录时后端校验密码，返回签名令牌。
5. 前端将登录态保存在浏览器本地存储，并在后续请求中携带 Bearer 令牌。
6. 后端从令牌解析当前用户，并检查受保护资源的访问权限。

密码不以明文保存。管理员账号通过环境变量 `ADMIN_ACCOUNT` 指定，普通账号默认使用 `student` 角色。

### 4.2 任务管理流程

```text
用户填写任务
    ↓
前端发送 POST / PATCH / DELETE 请求
    ↓
后端校验课程归属、字段格式和用户权限
    ↓
SQLite 写入或更新 tasks 表
    ↓
后端返回任务结果
    ↓
前端刷新列表和统计卡片
```

任务支持标题、所属课程、截止时间、优先级、备注和完成状态。任务完成时记录 `completed_at`，恢复未完成时清除该字段。

### 4.3 资料上传流程

1. 用户选择课程和本地文件。
2. 前端通过 multipart 请求上传文件。
3. 后端校验扩展名和文件大小，当前上限为 20 MB。
4. 文件保存到课程对应目录，元数据写入 `materials` 表。
5. 前端根据后端返回结果更新资料列表。

当前版本只完成资料保存、元数据显示和删除。`parse_status` 保留为后续解析流程的状态字段，尚未实现文本解析和 RAG。

### 4.4 AI 对话流程

1. 用户创建或复用一个会话。
2. 前端提交消息内容和可选的供应商配置。
3. 后端检查会话归属和供应商 Base URL。
4. 如果没有 API Key，后端返回本地演示模式回复。
5. 如果配置了 API，后端向 OpenAI 兼容接口发送请求。
6. 用户消息和助手回复写入 `messages` 表。
7. 上游 401、超时或网络异常时，后端返回统一的可读降级文案。

当前 AI 对话属于普通文本对话，模型请求不携带完整历史上下文，也不读取课程资料。RAG 和资料引用属于后续功能。

### 4.5 统计流程

统计接口从任务表聚合数据，返回：

- `total`：任务总数
- `completed`：已完成任务数
- `overdue`：未完成且已过截止时间的任务数
- `completion_rate`：`completed / total`
- `server_time`：服务器当前时间

课程和日期范围筛选由后端执行。日期范围按校园时区 UTC+8 解释，当前时间过滤字段为任务截止时间 `due_at`，不是完成时间 `completed_at`。

## 5. 数据库设计

### 5.1 数据表

| 表 | 主要用途 | 关键关系 |
| --- | --- | --- |
| `users` | 用户、密码哈希和角色 | 一个用户可拥有多个课程或任务 |
| `courses` | 课程名称、学期和所有者 | 与任务、资料、成员关联 |
| `course_members` | 用户与课程的成员关系 | 用户与课程多对多 |
| `tasks` | 学习任务、截止时间和完成状态 | 每条任务属于一个课程和用户 |
| `materials` | 上传资料元数据和解析状态 | 每份资料属于一个课程和上传者 |
| `conversations` | AI 会话 | 每个会话属于一个用户 |
| `messages` | 用户消息和助手回复 | 每条消息属于一个会话 |

### 5.2 数据持久化策略

- SQLite 开启外键约束。
- 数据库初始化在后端启动时执行，使用 `CREATE TABLE IF NOT EXISTS`。
- 任务完成时间在状态变化时同步更新。
- 课程仍有关联任务或资料时，删除操作返回 409，避免误删关联数据。
- 测试使用临时数据库路径，不覆盖开发数据库。

### 5.3 当前未建的数据结构

以下结构属于特色版规划，当前未实现：

- `material_chunks` 等资料切分表
- 向量索引或 embedding 存储
- `messages.type`、`citations` 等 RAG 引用字段
- `tasks.parent_task_id` 等 AI 子任务关联字段
- `courses.invite_code` 邀请码字段

## 6. API 设计

API 统一使用 `/api/v1` 前缀，并通过 Bearer Token 保护需要登录的接口。

### 6.1 API 分组

| 分组 | 典型接口 | 作用 |
| --- | --- | --- |
| 健康检查 | `GET /health` | 检查后端是否正常运行 |
| 认证 | `POST /auth/register`、`POST /auth/login`、`GET /auth/me` | 用户注册、登录和当前用户信息 |
| 用户管理 | `GET /users`、`PATCH /users/{id}/role` | 管理员查看用户和调整角色 |
| 课程 | `GET/POST /courses`、`GET/PATCH/DELETE /courses/{id}` | 课程创建、查询、修改和删除 |
| 任务 | `GET/POST /tasks`、`PATCH/DELETE /tasks/{id}` | 任务增删改查和状态管理 |
| 截止任务 | `GET /tasks/upcoming` | 查询 7 天内未完成任务 |
| 资料 | `GET /courses/{id}/materials`、`POST /materials`、`DELETE /materials/{id}` | 资料列表、上传和删除 |
| 会话 | `POST/GET /conversations` | 创建和查询会话 |
| 消息 | `POST/GET /conversations/{id}/messages` | 发送和读取 AI 消息 |
| 统计 | `GET /stats/overview`、`GET /stats/courses` | 总览和按课程统计 |

当前代码实际实现 25 个 API 端点。完整字段、请求体、响应示例和计划端点见 [04-api-spec.md](04-api-spec.md)。

### 6.2 错误与权限

- 未登录访问受保护接口返回 401。
- 非成员访问课程资源返回 403。
- 修改或删除他人资源时返回 404，避免暴露资源是否存在。
- 非法日期、非法字段和不符合约束的输入返回 422。
- 不支持的文件格式或超过 20 MB 的文件返回 400。
- 非空课程删除返回 409。
- AI 上游认证失败、超时或网络异常时返回统一的可读降级回复。

## 7. 安全与可靠性

### 7.1 已实现的安全措施

- 密码使用带盐哈希保存，不保存明文密码。
- 访问令牌由后端生成并签名。
- 资源访问由后端检查用户身份和资源归属，不能只依赖前端隐藏按钮。
- 管理员接口要求 `admin` 角色。
- 上传文件限制扩展名和大小。
- AI API Key 不写入数据库，也不应提交到 Git。
- AI 错误响应不向前端返回 API Key、上游响应或堆栈信息。
- 测试中的 API Key 仅为占位字符串，不是真实凭据。

### 7.2 当前边界

- 浏览器配置的 API Key 会保存在当前浏览器的 `localStorage`，不适合在共享电脑上保存。
- 当前项目面向本地课程演示，不提供生产级多租户、高并发、限流和完整运维能力。
- AI 请求允许 OpenAI 兼容的 HTTP(S) Base URL，生产部署时还需要增加域名白名单和私网地址限制。

## 9. 部署与演示

### 9.1 本地安装

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 9.2 启动后端

```powershell
..\run-backend.cmd
```

或者：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

### 9.3 启动前端

在另一个终端执行：

```powershell
..\run-frontend.cmd
```

或者：

```powershell
cd frontend
py -m http.server 5500
```

打开 `http://127.0.0.1:5500`，注册账号后即可使用。

### 9.4 答辩演示主线

建议按以下顺序控制在约 5 分钟：

1. 登录系统。
2. 查看课程和任务。
3. 新建一条近期截止任务。
4. 标记任务完成，观察统计变化。
5. 上传一份课程资料，展示资料列表和校验。
6. 发送一条 AI 学习计划问题。
7. 说明当前已实现功能和计划中的 RAG 等能力。

现场演示应以当前代码实际能运行的功能为准，不应把资料问答、RAG 或 AI 任务拆解演示成已完成能力。详细步骤见 [final-demo-checklist.md](final-demo-checklist.md)。

## 10. 当前限制与后续计划

### 10.1 当前限制

- 资料目前只保存文件和元数据，解析状态不会流转到可问答。
- AI 对话当前不携带完整历史上下文。
- 邀请码加入课程尚未实现。
- 教师角色可以分配，但教师专属权限仍需细化。
- 统计按任务截止时间筛选，尚无按完成时间的趋势分析。
- RAG、资料来源引用和 AI 任务拆解尚未实现。
- 真实用户调研、原型验证和完整用户体验测试尚未执行。

### 10.2 后续计划

1. 完善资料解析和状态流转。
2. 增加资料切分、向量索引、课程范围检索和来源展示。
3. 增加带编辑确认环节的 AI 任务拆解。
4. 完善多轮会话和历史会话切换。
5. 细化教师角色和课程协作机制。
6. 增加按完成时间的趋势统计。
7. 依据真实用户访谈和原型测试结果修订需求优先级。
